# Conformance

How oneyaml-go scores against the [yaml-test-suite](https://github.com/yaml/yaml-test-suite) and the oneyaml family's own cases, and every case it does not pass.

The cases run through [oneyaml-kit](https://github.com/recursive-ai-oss/oneyaml-kit), which drives the library through `Parse`, `Unmarshal`, `Marshal`, `ApplyPatch` and `ApplyMergePatch`. CI runs them on every push to `main` and every pull request. To run them yourself, use `bin/kit fast --adapter oneyaml-go` in a kit checkout, with `KIT_ONEYAML_GO_SRC` set to a checkout of this repository.

## Known deviations

Each is a difference in the Go value that `Unmarshal` into `any` produces. The `Document` and `Node` API keep the information.

| Case | What happens | Where to get the full information |
|---|---|---|
| `yts:UGM3@value` | The suite records `450` for `450.00`; the Core schema reads the float `450.0`, as the kit's corrected expectation does. | none needed |
| `own:schema/unresolved-tag-is-kept` | A local tag the schema does not know, such as `!color red`, is dropped; the value is the string `red`. | `Node.ExplicitTag`, `Node.TagAsWritten` |
| `own:schema/local-tag-on-a-collection-is-kept` | A local tag on a mapping or sequence is dropped. | `Node.ExplicitTag` |
| `own:schema/global-tag-uri-is-kept` | A global tag such as `tag:example.com,2000:shape` is dropped. | `Node.ExplicitTag` |
| `own:schema/code-constructing-tags-are-kept-or-refused` | A tag such as `!!python/object/apply:os.system` is dropped and the value read as plain data. Nothing is constructed or run. | `Node.ExplicitTag` |
| `own:schema/mapping-as-a-mapping-key` | A mapping used as a key is refused, because a Go map cannot hold it. | `Parse`, `Node.Entry` |
| `own:schema/sequence-as-a-mapping-key` | The same for a sequence used as a key. | `Parse`, `Node.Entry` |

The kit fails the run if a case not on this list fails, or if a listed case starts to pass.
